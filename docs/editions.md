# 多底座与构建策略

本页说明 Linxira 的近期构建路线与承诺边界。站点公告见
[近期路线](https://linxira-os.github.io/zh/blog/editions-and-build-strategy/)。

## 定位

Linxira 不是从零构建的发行版，而是**上游发行版之上的可移除层**：catalog、
事务计划/确认/回执、签名仓库、配置入口、更新提醒、崩溃监视与欢迎中心。
每种底座只负责提供内核、硬件 enablement 与基础用户态。

## 近期路线

- **Arch x86_64**：当前主线。滚动更新，计划每月一次 ISO 快照；卸掉
  `linxira-*` 就回到原生 Arch。
- **Ubuntu 短期验证**：先用 26.10（内核 7.3）做验证镜像，必要时跟进
  27.04 / 27.10，直到下一个 LTS（28.04）。这些是 9 个月生命周期的验证版，
  不是长期产品。
- **NixOS**：不作为产品线。Zeta 仓库已有 Nix 构建，容器/VM 里用上游 Nix
  即可；我们不需要维护 NixOS 配置。

| 线 | 底座 | 定位 | 更新节奏 | 退出方式 | 状态 |
|---|---|---|---|---|---|
| Arch x86_64 | Arch Linux | 主力开发机，也可推理 | 滚动；计划月度 ISO 快照 | 卸掉 `linxira-*` 回到原生 Arch | 当前主线 |
| Ubuntu 短期验证 | 26.10 / 27.04 / 27.10 | 验证 apt 后端、桌面、驱动、ARM 白名单 | 跟随 interim，9 个月 | 重装；层可移除 | 验证中 |
| Ubuntu LTS（未来） | 26.04 LTS 或 28.04 LTS | 推理机、科学计算、国产 GPU | LTS 定点 + 上游安全 | 衍生层可移除，不是滚动退出 | 待定 |

验证镜像会明确标注 **“验证版，非长期支持，EOL 日期”**，不进入支持矩阵，
不做长期承诺。

## Ubuntu 时间线

- 26.04 LTS：2026-04-23 发布，标准安全维护到 2031-05，ESM 到 2036。
- 26.10：2026-10 发布，9 个月支持，2027-07 结束。
- 27.04 “Tenacious T-Rex”：2027-04-22，仍是 9 个月 interim。
- 27.10：2027-10，interim。
- 下一个 LTS：28.04（2028-04）。

2027 年没有 LTS。要 LTS + 7.3 内核，决策点是 **26.04.2（2027-02-18）**：
如果 HWE 跟进 7.3 且硬件验证通过，就把长期基线切到 26.04 LTS；否则继续用
27.04 验证，26.10 在 2027-07 EOL 前必须迁走或下线。

## 中国网络与镜像

- **Arch**：国内镜像完整（TUNA、USTC、阿里云等）；月度 ISO 计划放
  GitCode / 国内对象存储。
- **Ubuntu**：官方归档有国内镜像（TUNA、USTC、阿里云、华为云等）；apt 源与
  ISO 可走国内。安装器会提供国内源选项。
- **国产 GPU**：摩尔线程、昇腾等驱动与工具链以 Ubuntu 为主。
- **DGX Spark / N1X**：NVIDIA DGX OS 基于 Ubuntu 26.04 LTS ARM64，但下载可能
  受账号/网络限制；只对白名单机型支持，不承诺通用 ARM。
- **NixOS**：镜像访问在国内不稳定，不作为产品入口。

## 构建与事务契约

- **catalog** 是软件与目标平台的唯一真相；每个应用的目标包按 edition 映射，
  不在 UI 或安装器里硬编码包名。
- **components** 保留 `plan → confirm → apply → receipt`；执行层按 edition
  选择后端：
  - Arch：固定 argv `pacman`；
  - Ubuntu：固定 argv `apt-get` / `dpkg-query`。
- **update / config-hub** 通过 edition 适配器选择源与更新方式，UI 共用同一套
  状态 schema。
- **ISO** 两条线各自维护构建脚本，但共用选择/确认/回执的 UX。

## 边界

1. 薄层、可退出：Arch 卸掉 `linxira-*` 后仍是原生 Arch；Ubuntu 验证镜像同样
   保持层可移除。
2. 只带常用软件，不塞赞助商软件或奇怪的系统组件。
3. 默认保守的供应链：Arch 不开 AUR；Ubuntu 不开未审核 PPA；厂商 deb 审核后
   进入签名仓库；不推荐 `curl | sh`。
4. 不自建内核：Arch 用官方最新；Ubuntu 用 HWE/厂商内核；没有完整自动化流水线
   之前不做 v3 / CachyOS 派生内核。
5. AI 可选：默认不自动运行 agent；crash-watch 默认 0 token 分流，用户触发才
   启动，本地只读、不上传。
